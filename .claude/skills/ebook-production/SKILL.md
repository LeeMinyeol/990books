# 전자책 제작

## 원칙
책 한 권은 **독자가 결과물 하나를 손에 쥐는 순서**다. 정보를 모아 놓은 글이 아니다. 모든 장은 "이 장을 넘기면 독자의 화면에 무엇이 생기는가"로 설명할 수 있어야 한다.

책마다 코드를 새로 짜지 않는다. 내용은 `src/books/<slug>/book.json`에 데이터로만 넣는다. 형식의 예시는 `src/books/insta-month/book.json`이다(내용은 임시 문구라 본보기가 아니다).

"확인 필요", "미정" 같은 표시를 남긴 채 다음 사람에게 넘기지 않는다. 검사기가 불합격으로 잡는다. 확인할 수 없으면 멈추고 사용자에게 묻는다.

## 시작 전에 읽는다
1. `CLAUDE.md`의 "왜 돈을 내는가", "상품 구성", "내용 규칙", "책 형식"
2. `docs/writing-style.md` 5장 (전자책 규칙)
3. `src/lib/book.ts` (데이터 타입)

## 1단계. 주제 카드를 쓴다
주제는 조사 시트의 "책 기획" 탭에서 고른다(주소와 구조는 `docs/research-sheet.md`). 사용자가 고른 줄을 출발점으로 삼고, 그 줄의 상태를 "선정"으로 바꾼다. 시트의 내용은 제목만 보고 쓴 가안이므로 그대로 옮기지 말고 2단계에서 확인하며 고친다.

`src/books/<slug>/brief.md`에 아래 칸을 채운다.

```markdown
# 주제 카드: <slug>
- 종류: mini / kit / deep 중 하나
- 분야와 세부 주제: (예: AI, 인스타그램)
- 독자의 상황: (한 문장. "~하는 사람"이 아니라 "~을 하는 중이라면")
- 독자가 지금 막힌 곳: (구체적인 장면 한 문장)
- 그 도구를 처음 쓰는 독자인가: 예 / 아니오
- 결과물 하나: (다 따라 하면 화면에 남는 것. 파일 이름이나 화면으로 말한다)
- 걸리는 시간: (분)
- 필요한 도구와 버전·요금제: (도구마다 한 줄. 2단계에서 확인한 뒤 채운다)
- 추가 비용: (원. 2단계에서 확인한 뒤 채운다)
- 들어 있는 파일: (입력값 몇 개, 템플릿 무엇)
- 돈 낼 이유 넷 중 셋: 파일 / 완주 설계 / 막히는 지점 / 정리 중 해당하는 것과 근거
- 같은 주제의 다른 99BOOKS 책과 겹치지 않는 점:
```

- "필요한 도구와 버전·요금제", "추가 비용" 두 칸만 1단계에서 "2단계에서 확인"이라고 적어 둘 수 있다. 나머지 칸은 1단계에서 모두 채운다. 채울 수 없으면 사용자에게 묻는다.
- **분야**는 결과물을 만드는 주 도구로 정한다(가안). AI 도구(클로드, 챗GPT 등)로 만들면 `AI`, 노션으로 만들면 `노션`, 스프레드시트·SQL로 만들면 `데이터 분석`, 유튜브 채널을 다루면 `유튜브 운영`이다. 이 넷에 들지 않으면 사용자에게 묻는다.
- **세부 주제**는 독자가 결과물을 쓰는 곳이다(인스타그램, 스마트스토어, 가계부).

| 칸 | 나쁜 예 | 좋은 예 |
|---|---|---|
| 독자의 상황 | 인스타그램에 관심 있는 사람 | 스토어를 운영하면서 인스타 계정을 혼자 올리는 중이라면 |
| 막힌 곳 | 콘텐츠 만들기가 어렵다 | 매일 저녁 "오늘 뭐 올리지"에서 30분이 간다 |
| 결과물 | 인스타 운영 노하우 | 날짜·주제·제목·형식이 채워진 30일 계획표 한 장 |
| 걸리는 시간 | 10분 (재 보지 않은 숫자) | 30분 (장 수와 입력값 수로 어림한 값. 원고를 다 쓴 뒤 다시 본다) |

## 2단계. 출처를 모은다
- 서로 다른 사이트 3곳 이상, 도구의 공식 문서 1개 이상.
- `src/books/<slug>/sources.md`에 `content-review` 스킬 1단계의 표 형식으로 적는다.
- 출처를 읽을 때마다 본문 글자를 `.research/<slug>/<번호>-<사이트>.txt`로 저장한다(나중에 겹침 검사에 쓴다).
- 출처는 **무엇이 사실인지** 확인하는 데만 쓴다. 목차, 예시, 프롬프트 문구는 가져오지 않는다.
- 공식 문서로 도구의 요금제·버전·추가 비용을 확인해서 주제 카드의 남은 두 칸을 채운다.
- **두 칸을 채우지 못했으면 여기서 멈추고 사용자에게 알린다.** 3단계로 가지 않는다. 뼈대만 먼저 달라는 요청을 받았을 때는 뼈대 맨 위에 "잠정"이라고 적고, 확인되지 않은 것을 목록으로 붙인다.

## 2-1단계. 화면을 확인한다
원고를 쓰기 전에, 책이 다루는 도구의 버튼 글자·아이콘·메뉴 위치를 확인한다. 공식 문서에 한국어 화면이 충분하지 않으면 사용자에게 캡처를 부탁한다(필요한 화면 목록을 표로 드린다). 캡처는 `.research/<slug>/captures/`에 두고 책에 넣지 않는다. 확인한 글자는 `outline.md`의 "실제 화면에서 확인한 글자"에 적고, 원고와 그림은 이 기록대로 쓴다. 같은 도구를 쓰는 앞 책의 기록이 있으면 그것을 먼저 본다.

## 3단계. 뼈대를 짠다
결과물에서 거꾸로 짠다. "결과물이 나오려면 바로 전에 무엇이 있어야 하나"를 반복해서 단계 목록을 만든 뒤 앞에서부터 번호를 붙인다. 뼈대에는 장마다 "이 장을 넘기면 화면에 생기는 것"과 입력값·이미지 중 무엇이 들어가는지 적는다.

| 종류 | 구성 | 분량 기준 (`book-check`가 본다) |
|---|---|---|
| mini | 표지 1 + 준비물 1 + 따라 하기 6~11 + 요약 1 + 다음편 1 | 10~15장, 입력값 3개 이상, 30분 이하 |
| kit | 표지 1 + 준비물 1 + 따라 하기 21~36 + 요약 1 + 다음편 1 | 25~40장, 입력값 8개 이상, 60분 이하 |
| deep | 위와 같은 슬라이드 묶음(표지·준비물·요약·다음편 + 핵심 단계) + `chapters/NN-이름.md` 5~7개 | 챕터 합계 공백 제외 15,000~25,000자 |

- 장 종류는 `cover`, `checklist`, `step`, `summary`, `next` 다섯 가지뿐이다. 새 종류를 만들지 않는다. "막히는 지점"은 따로 장을 만들지 않고 해당 따라 하기 장의 본문에 확인 방법으로 넣는다.
- 따라 하기 장의 제목은 모두 동작이다("30일 게시 계획표를 만들어요"). 주제어("계획표")나 명사형("계획표 만들기")으로 쓰지 않는다.
- 글만 있는 장(입력값도 이미지도 없는 장)은 연속 2장까지만.
- **입력값**은 독자가 복사해서 붙여넣는 모든 것이다. AI에 보내는 프롬프트, 수식, 열 이름 목록, 설정값이 모두 해당한다.
- deep의 챕터는 아래 여섯 소제목을 이 글자 그대로, 이 순서로 쓴다. 따라 하기 안의 단계는 `### 1. 동작` 형식으로 쓴다.
  `## 이 장을 마치면` → `## 먼저 알아둘 것` → `## 따라 하기` → `## 자주 막히는 곳` → `## 나쁜 예와 좋은 예` → `## 점검표`
- deep의 챕터 파일은 이렇게 쓴다. 예시는 `docs/samples/deep-chapter-sample.md`(검사기 합격본)다.
  - 첫 줄은 `# 챕터 제목`. 파일 이름 순서(`01-`, `02-`)가 장 순서다.
  - 입력값 박스는 코드 울타리 첫 줄에 이름을 적는다: ` ```입력값 1 `. 번호는 책 전체에서 1부터 이어 붙인다. 참고용은 ` ```작성 예시 `.
  - "자주 막히는 곳"과 "나쁜 예와 좋은 예"는 표로, "점검표"는 `- [ ] 항목`으로 쓴다. 이미지는 `![설명](/books/<slug>/파일)`.
- 뷰어에서 deep은 표지 → 준비물 → 챕터(긴 글형) → 핵심 단계(슬라이드) → 요약 → 다음편 순서로 나온다. 핵심 단계 장은 챕터에서 한 일을 되짚는 2~5장이다.
- 만드는 중인 책은 `book.json`에 `"draft": true`를 넣는다. 홈에 나오지 않고 개발 화면에서만 주소로 열린다. 사용자가 최종 확인한 뒤에 지운다.

## 4단계. 따라 하기 장을 쓴다
장 하나는 네 조각이다. 1과 2는 반드시 있고, 3과 4는 해당할 때 넣는다.
1. **제목**: 이 장에서 하는 동작. 22자 이하.
2. **본문 1~2문장**: 무엇을 한다 + 그러면 어떻게 되는지(확인 방법). 문장당 40자 이하. 굵게는 독자가 누르거나 바꿀 것 1곳.
3. **박스**(`prompt`): 복사해서 붙여넣을 것이면 `label`을 "입력값 1", "입력값 2"처럼 1부터 차례로 붙인다. 참고로 보여주기만 하는 것이면 `label`을 "작성 예시"로 한다. 입력값 개수에는 "입력값 N"만 센다.
4. **이미지**(`image`): 그 동작을 하는 화면의 목업. `docs/image-style.md` 규칙대로 `src/books/<slug>/figures/<이름>.json`에 그림 설명을 쓰고 `node scripts/mockup.mjs <slug>`로 SVG를 만든다. 실제 화면 캡처는 책에 넣지 않는다. `alt`에 그림이 보여주는 동작을 적는다.

입력값에 독자가 바꿀 곳이 있으면 `[ ]`로 표시하고, **`[ ]`마다 무엇을 넣을지 그 장의 본문이나 앞 장의 작성 예시가 알려줘야 한다.**

| 조각 | 나쁜 예 | 좋은 예 |
|---|---|---|
| 제목 | 프롬프트 입력 | 내 계정을 클로드에게 알려줘요 |
| 본문 | 프롬프트를 잘 작성하는 것이 중요합니다. 아래 내용을 참고하여 상황에 맞게 수정해서 사용하세요. | 아래 입력값을 복사해서 **[ ]만 바꿔** 붙여넣어요. |
| 확인 방법 | (없음) | 표가 나오면 성공이에요. 글로만 나오면 "표로 다시 정리해줘"라고 보내요. |
| 입력값 | 인스타 콘텐츠 만들어줘 | 나는 [판매하는 것]을 파는 사람이야. 손님은 [주요 손님]이고 … 콘셉트를 3가지로 제안해줘. |

한 장에 동작이 둘이면 두 장으로 나눈다. "A를 누르고 B를 입력해요"는 두 장이다.

## 5단계. 표지를 만든다
- **제목**: 도구 + 결과물 + 걸리는 시간. 12~32자. 예: "클로드로 인스타 한 달치 콘텐츠, 하루 만에 뽑기". 제목의 시간과 `minutes`, 칩의 시간은 서로 어긋나지 않게 한다.
- **부제**: 받게 되는 결과물을 구체적으로 한 문장. 본문이 실제로 하는 방식과 같은 말로 쓴다(나눠서 요청하는 책이면 "한 번에"라고 쓰지 않는다).
- **칩** 2~4개: 걸리는 시간, 분량, 필요한 도구.
- **미리보기 이미지**: 완성된 결과물. 도구의 첫 화면이나 로고가 아니다.
- **색**: `src/lib/palette.json`에서 고른다. 목록에 없는 색은 쓰지 않는다.
  1. `fits`가 주제와 맞는 색을 찾는다. 둘 이상 맞으면 목록에서 위에 있는 색이다.
  2. 그 색을 같은 분야(`category`)의 다른 책이 쓰고 있으면 다음으로 맞는 색으로 넘어간다.
  3. 맞는 색이 남지 않으면 같은 분야에서 아직 안 쓴 색 중 목록에서 가장 위의 색이다.
  4. `onAccent`는 목록에 적힌 값을 그대로 쓴다.

| 항목 | 나쁜 예 | 왜 |
|---|---|---|
| 제목 | 인스타로 월 300만 원 버는 법 | 수익 약속. 결과물이 아니다 |
| 제목 | 인스타그램 콘텐츠 가이드 | 도구도, 결과물도, 시간도 없다 |
| 부제 | 누구나 쉽게 따라 하는 완벽 가이드 | 무엇을 받는지 알 수 없다 |

## 6단계. 준비물 장을 쓴다
갱신을 약속하지 않는 대신 여기에 기준을 남긴다.
- `checkedAt`: 작성 시점 (YYYY-MM-DD). 마지막으로 화면과 출처를 확인한 날이다.
- `items`: 도구마다 한 줄. `note`에 2단계에서 확인한 **버전이나 요금제, 화면 기준 시점**을 적는다. 예: `"label": "클로드", "note": "무료 요금제, 2026년 11월 화면 기준"`
- `totalCost`: 추가 비용을 금액으로.
- 확인한 것만 적는다. "최신 버전", "확인 필요"라고 적지 않는다. 확인하지 못했으면 2단계로 돌아간다.

## 7단계. 요약과 다음편을 쓴다
- 요약: 독자가 만든 것 3~5개를 명사로. "배운 것"이 아니라 본문에서 실제로 "생긴 것"을 적는다.
- 다음편: 같은 독자가 다음에 만들 결과물. 소개 문장은 이 책의 결과물과 어떻게 이어지는지 사실대로 쓴다. 가격은 `src/lib/pricing.ts`의 값과 같게(`book-check`가 본다).

## 8단계. 데이터를 넣고 등록한다
1. `src/books/<slug>/book.json`을 타입에 맞춰 쓴다. `kind`, `accent`, `onAccent`, `category`, `topic`, `tools`, `extraCost`, `minutes`를 모두 채운다.
2. 이미지는 `public/books/<slug>/`에 넣는다.
3. `src/books/index.ts`에 책을 추가하고, `src/books/coming.ts`에 같은 책이 있으면 지운다.

## 9단계. 검사한다
```bash
node scripts/book-check.mjs <slug>
node scripts/style-check.mjs src/books/<slug>/book.json --type slide
npx tsc --noEmit
npx eslint src
```
deep이면 챕터마다 `node scripts/style-check.mjs src/books/<slug>/chapters/<파일> --type deep`도 돌린다.

✗가 0개가 될 때까지 고친다. 그다음 처음부터 끝까지 한 번 읽으며 본다.
- [ ] 제목·부제·칩의 약속(결과물, 시간)이 본문에서 실제로 이뤄지는가
- [ ] 입력값의 `[ ]`마다 넣을 것을 본문이나 작성 예시가 알려주는가
- [ ] 앞 장을 가리키는 말("위 3가지")이 그 장의 실제 결과와 같은가

마지막으로 브라우저에서 뷰어 `/books/<slug>/read`를 PC(1280px)와 모바일(375px)로 열어 첫 장부터 마지막 장까지 넘기며 글이 잘리거나 넘치는 장이 없는지 본다. 결제 전에는 앞 3장만 열리므로, `.env.local`에 `BOOKS_UNLOCK_ALL=1`이 있는지 먼저 확인한다(설명은 `.env.local.example`).

## 10단계. 상세페이지와 검수로 넘긴다
1. `detail-page` 스킬로 상세페이지 구성을 만든다.
2. `content-review` 스킬로 검수한다. 불합격이면 고치고 다시 검수한다.

## 11단계. 보고한다
- 책 이름, 종류, 장 수, 입력값 수
- 검사 결과
- 검수 판정과 보고서 위치
- 확인하지 못한 것 (예: 로그인이 필요해 실제 화면을 보지 못한 장 번호)
- 사용자가 정해야 하는 것

## 자주 하는 실수
| 실수 | 고치는 법 |
|---|---|
| 도구의 기능을 설명하는 장이 이어진다 | 장마다 "이 장을 넘기면 화면에 무엇이 생기나"를 적어 본다. 답이 없으면 그 장을 지우거나 다음 동작 장에 한 문장으로 합친다 |
| 출처의 목차 순서를 따라간다 | 3단계처럼 결과물에서 거꾸로 다시 짠다 |
| 입력값이 "~해줘" 한 줄이다 | 역할, 상황, 원하는 형식, 개수를 넣고 바꿀 곳을 `[ ]`로 표시한다 |
| 준비물 장에 "최신 버전"이나 "확인 필요"라고 쓴다 | 2단계로 돌아가 공식 문서로 확인한 요금제와 화면 기준 시점을 적는다 |
| 재 보지 않은 시간을 약속한다("10분 만에") | 장 수와 입력값 수로 어림하고, 종류별 상한(mini 30분, kit 60분) 안에서 넉넉하게 적는다 |
| "막히는 지점" 같은 새 장 종류를 만든다 | 다섯 가지 장 종류만 쓴다. 막히는 지점은 따라 하기 장의 확인 방법에 넣는다 |
| 미니북을 심화 가이드의 앞부분으로 만든다 | 미니북은 다른 결과물 하나를 만든다. 주제 카드의 마지막 칸을 다시 쓴다 |
