# 규칙을 안내 문서로 남겨요

## 이 장을 마치면

연습 폴더 맨 위에 정리 규칙을 적은 `CLAUDE.md`가 생겨요. 새로 생긴 파일 5개를 "정리해줘" 한마디로 정리해서, 규칙이 다음 세션에서도 통하는 것을 확인해요.

![CLAUDE.md의 세 구역: 정리 규칙, 옮기지 말 파일, 정리해줘라고 하면](/books/claude-code-start/ch6-claude-md.svg)

## 먼저 알아둘 것

`CLAUDE.md`는 클로드 코드가 세션을 시작할 때마다 먼저 읽는 안내 문서예요. 공식 안내에 따르면 작업 폴더 맨 위에 이 이름의 파일을 두면, 그 폴더로 새 세션을 열 때마다 내용을 읽고 일을 시작해요.

지금까지는 정리할 때마다 4장의 긴 입력값을 붙여넣어야 했어요. 규칙을 `CLAUDE.md`에 적어 두면 그럴 필요가 없어요. 공식 안내도 "같은 설명을 다시 입력하게 될 때"를 이 문서에 적을 때로 꼽아요.

다만 이 문서는 지켜야 하는 설정이 아니라 읽고 참고하는 글이에요. 공식 안내에 따르면 지시가 모호하거나 서로 부딪치면 그대로 따르지 않을 수 있어요. 그래서 규칙은 확인할 수 있을 만큼 구체적으로 써요. "깔끔하게 정리"보다 "메모는 문서 폴더로"가 잘 지켜져요.

길이는 짧게 둬요. 공식 안내는 파일 하나를 200줄 이하로 쓰라고 권하고, 제목과 글머리표로 묶은 글이 긴 문단보다 따르기 쉽다고 적어요. 이 장에서 만드는 문서는 30줄이 안 돼요.

파일 이름 끝의 `.md`는 마크다운이라는 글 형식을 뜻해요. 줄 맨 앞에 `#`을 붙이면 제목, `-`를 붙이면 글머리표가 돼요. 특별한 프로그램 없이 메모장으로 열고 고칠 수 있는 글자 파일이에요.

하나를 더 더해요. "정리해줘"라고 할 때 계획 모드로 요청하는 거예요.

안내 문서에 "계획을 먼저 보여준다"고 적어 두면 대개 그렇게 하지만, 반드시 지킨다는 보장은 없어요. 계획 모드에서는 승인하기 전까지 파일 고치기가 아예 막혀 있으니, 계획부터 받는 순서가 확실해져요.

## 따라 하기

### 1. 연습 폴더를 편집 자동 수락으로 열어요

**새로 만들기**로 새 세션을 열고, 폴더 칸에서 `클로드연습`을 고른 뒤 권한 모드를 **편집 자동 수락**으로 해요.

성공: 폴더 칸에 `클로드연습`, 권한 모드 칸에 "편집 자동 수락"이 보여요.

이번에는 안내 문서 하나만 만들기 때문에 묻지 않고 진행해도 돼요. 5장의 세션을 이어서 써도 괜찮아요.

### 2. 안내 문서를 만들어 달라고 해요

아래 입력값을 그대로 붙여넣어 보내요. 첫 줄 아래의 내용이 곧 `CLAUDE.md`에 들어갈 글이에요.

```입력값 10
아래 내용 그대로 이 폴더 맨 위에 CLAUDE.md 파일을 만들어줘. 다른 파일은 건드리지 마.

# 이 폴더에서 일하는 규칙

## 정리 규칙
- 메모(.txt)는 "문서", 표(.csv)는 "표", 그림(.svg)은 "그림" 폴더로 옮긴다
- 새 이름은 날짜_내용_순번 (예: 2026-11-03_회의메모_01.txt)
- 날짜는 YYYY-MM-DD. 이름에 날짜가 없으면 "날짜없음"
- "최종", "수정", "(2)" 같은 말은 새 이름에서 뺀다
- 새 이름에 < > : " / \ | ? * 를 쓰지 않고, 끝에 공백이나 마침표를 두지 않는다
- 같은 폴더에 같은 이름이 생기면 순번을 하나 올린다

## 옮기지 말 파일
- CLAUDE.md, 변경기록.csv

## "정리해줘"라고 하면
1. 폴더 맨 위에 있는 파일만 대상으로 계획표를 먼저 보여준다 (지금 이름 / 옮길 폴더 / 새 이름 / 비고)
2. 승인을 받은 뒤에만 옮긴다
3. 옮길 때마다 변경기록.csv 끝에 한 줄씩 이어 적는다. 있던 줄은 지우지 않는다
4. 끝나면 옮긴 수, 옮기지 못한 수, 남은 파일을 알려준다
5. 파일을 지우지 않는다
```

성공: 연습 폴더 맨 위에 `CLAUDE.md`가 생겨요.

문서는 세 구역으로 나뉘어 있어요. 첫 구역은 4장에서 정한 규칙, 둘째 구역은 5장에서 겪은 "기록 파일이 휩쓸리는 문제"를 막는 줄이에요. 셋째 구역은 4장과 5장의 순서를 다섯 줄로 줄인 거예요.

문서 안의 규칙은 "옮긴다", "뺀다"처럼 짧은 명령으로 끝나요. 사람에게 보여줄 글이 아니라 클로드 코드가 읽을 규칙이라 짧게 쓰는 편이 나아요. 규칙을 바꿨다면 해당 줄을 먼저 고친 뒤 보내요.

셋째 구역의 5번 줄 "파일을 지우지 않는다"는 연습이 끝난 뒤에도 남겨 두는 편이 좋아요. 정리를 맡기는 동안 지우기만큼은 내가 직접 하겠다는 약속이에요.

### 3. 메모장으로 열어 내용을 확인해요

파일 탐색기에서 `클로드연습` 폴더 맨 위의 `CLAUDE.md`를 메모장으로 열어 입력값 10과 같은지 봐요.

성공: 세 구역이 모두 들어 있어요.

안 되면: 윈도우에서 `.md` 파일을 두 번 눌렀을 때 열 프로그램을 물으면 메모장을 골라요.

`CLAUDE.md`는 그냥 글자 파일이라 메모장에서 직접 고쳐도 돼요. 규칙을 바꾸고 싶을 때는 클로드 코드에 부탁하지 않고 이 파일을 열어 해당 줄만 고쳐도 돼요.

메모장에서 고친 내용은 저장한 뒤 새로 여는 세션부터 반영돼요. 안내 문서는 세션을 시작할 때 읽히기 때문이에요.

### 4. 새 파일 5개를 만들어요

같은 세션에서 아래 입력값을 보내 "정리해줘"를 시험할 새 파일을 만들어요.

```입력값 11
정리 연습용으로 이 폴더 맨 위에 가짜 파일 5개를 더 만들어줘.
메모(.txt) 2개, 표(.csv) 2개, 그림(.svg) 1개. 이름은 어지럽게 하고, 실제 사람 이름이나 연락처는 넣지 마.
```

성공: 폴더 맨 위에 새 파일 5개가 생기고, 세 폴더 안에는 아무 변화가 없어요.

### 5. 새 세션에서 "정리해줘"만 보내요

**새로 만들기**로 세션을 열고 `클로드연습`을 고른 뒤 권한 모드를 **계획**으로 바꾸고, 입력 상자에 **정리해줘** 네 글자만 보내요.

성공: 맨 위의 새 파일 5개만 담긴 계획표가 4장의 규칙과 같은 모양으로 나와요. 세 폴더와 `CLAUDE.md`, `변경기록.csv`는 계획표에 없어요.

안 되면: 규칙과 다르게 정리하려고 하면 안내 문서를 만들기 전에 연 세션이에요. 새 세션을 열어 다시 보내요.

안 되면: 정리된 폴더 안의 파일까지 계획표에 나오면 "맨 위에 있는 파일만" 줄이 빠진 거예요. `CLAUDE.md`의 셋째 구역 1번 줄을 확인하고 고쳐요.

`CLAUDE.md`는 세션을 시작할 때 읽기 때문에 시험은 새 세션에서 해요. 계획표가 4장보다 짧아도 정상이에요. 긴 규칙을 붙여넣지 않았는데도 같은 모양의 계획표가 나왔다면, 안내 문서를 읽고 따른 거예요.

계획표가 규칙대로면 확인 없이 진행하는 답으로 승인해요. 끝난 뒤 `변경기록.csv`를 열어, 5장의 20줄 아래에 새 줄 5개가 이어 붙었는지 확인해요.

## 자주 막히는 곳

| 증상 | 원인 | 해결 |
|---|---|---|
| "정리해줘"에 규칙과 다르게 정리하려고 해요 | 안내 문서를 만들기 전에 연 세션이에요 | 새 세션을 열어 다시 보내요. 안내 문서는 세션을 시작할 때 읽어요 |
| 정리된 폴더 안의 파일까지 계획표에 나와요 | "맨 위에 있는 파일만"이라는 줄이 빠졌어요 | `CLAUDE.md`의 셋째 구역 1번 줄을 확인하고 고쳐요 |
| 변경기록.csv의 예전 줄이 사라졌어요 | "끝에 이어 적기"가 문서에 없었어요 | 셋째 구역 3번 줄을 넣고, 사라진 줄은 5장 기록을 참고해 다시 적어 달라고 해요 |
| CLAUDE.md가 "문서" 폴더로 옮겨졌어요 | 옮기지 말 파일 구역이 없었어요 | 폴더 맨 위로 되돌리고 둘째 구역을 넣어요. 맨 위에 있어야 세션마다 읽혀요 |

규칙이 지켜지지 않을 때 먼저 볼 곳은 문서의 표현이에요. "정리한다"처럼 넓은 말은 "메모는 문서 폴더로 옮긴다"처럼 무엇을 어디로 하는지가 드러나게 바꿔요. 같은 내용을 두 군데 다르게 적은 줄이 없는지도 봐요.

안내 문서는 한 번 쓰고 끝내는 글이 아니에요. 공식 안내는 클로드 코드가 같은 실수를 두 번째로 할 때 그 내용을 문서에 더하라고 권해요. 예를 들어 그림 파일 이름에서 날짜를 자꾸 빼먹는다면, 정리 규칙 구역에 그 내용을 한 줄 더해요.

## 나쁜 예와 좋은 예

| 구분 | 안내 문서에 쓴 글 | 결과 |
|---|---|---|
| 나쁜 예 | 파일을 보기 좋게 정리해 주세요 | 무엇이 보기 좋은지는 클로드 코드가 정해서, 세션마다 결과가 달라질 수 있어요 |
| 좋은 예 | 메모(.txt)는 "문서" 폴더로 옮긴다 | 옮길 파일과 갈 곳이 정해져 있어서 매번 같은 결과가 나와요 |
| 나쁜 예 | 정리 방법을 긴 문단 하나로 설명해요 | 중간의 조건 하나를 놓치기 쉬워요 |
| 좋은 예 | 제목 아래 한 줄에 규칙 하나씩 적어요 | 어느 규칙이 지켜지지 않았는지 줄 단위로 찾을 수 있어요 |

첫 번째 쌍의 차이는 확인할 수 있느냐예요. 좋은 예는 결과를 보고 지켰는지 아닌지 바로 판단할 수 있어요.

두 번째 쌍의 차이는 생김새예요. 한 줄에 규칙 하나면, 고칠 때도 그 줄만 바꾸면 돼요.

## 점검표

- [ ] 연습 폴더 맨 위에 `CLAUDE.md`가 있어요
- [ ] 메모장으로 열어 세 구역이 모두 들어 있는 것을 봤어요
- [ ] 새 파일 5개를 만들었어요
- [ ] 새 세션의 계획 모드에서 "정리해줘"만으로 새 파일 5개의 계획표를 받았어요
- [ ] 변경기록.csv에 새 줄 5개가 이어 붙었어요
