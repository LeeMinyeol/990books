# 책 그림 규칙 (설명용 목업)

모든 책의 그림은 이 규칙으로 그린다. 손으로 좌표를 잡지 않고 `scripts/mockup.mjs`에 그림 설명(JSON)을 넣어 만든다. 규칙을 바꿀 때는 이 문서와 스크립트를 함께 고친다.

정한 날: 2026-11-14. 테스트 책 1장 그림을 `impeccable` 스킬 기준(위계, 글자, 정렬, 여백)으로 진단한 결과다.

## 1. 왜 이 규칙인가 (진단에서 나온 문제)
| 문제 | 그림 | 고친 규칙 |
|---|---|---|
| 설명 말풍선이 화면 글자보다 크고 굵어서, 봐야 할 버튼보다 설명이 먼저 보였다 | 도움말 메뉴 | 3. 설명 글자는 화면 글자보다 크지 않게 |
| 내용이 왼쪽 위에 붙고 오른쪽 아래가 비었다. 설명은 가리키는 곳과 멀었다 | 도움말 메뉴 | 2. 묶음 전체를 가운데에, 4. 번호표는 대상 바로 옆에 |
| 창 전체를 그려서 모바일(325px)에서는 글자가 4px 안팎이 됐다 | Code 탭 | 2. 화면의 한 부분만 크게 그린다 |
| 배경색이 그림마다 달랐다 | 1장 전체 | 5. 바탕은 한 가지 색 |
| 확인하지 않은 버튼 글자("계속하기")를 그렸다 | 로그인 | 7. 확인한 글자만 쓴다 |

## 2. 캔버스와 구도
- 크기 1280×800(16:10). 파일은 SVG.
- 그림이 실제로 보이는 폭: PC 챕터 678px, PC 슬라이드 430px, 모바일 325px(2026-11-14 측정). 가장 작은 325px에서는 원본이 약 4분의 1로 줄어든다.
- **한 그림에는 화면의 한 부분만** 그린다. 창 전체를 그리지 않는다. 독자가 할 동작 하나와 그 주변만 크게 보여준다.
- 내용(화면 조각)과 설명 목록을 한 묶음으로 보고, 묶음 전체를 캔버스 가운데에 둔다. 바깥 여백은 위아래·양옆 모두 72px 이상.
- 설명 목록은 화면 조각의 오른쪽에 둔다(기본). 화면 조각이 가로로 길면 아래에 둔다.

## 3. 글자
| 쓰임 | 크기(원본 px) | 굵기 | 모바일에서 | PC 챕터에서 |
|---|---|---|---|---|
| 화면 속 글자 | 40 | 400 | 약 10px | 약 21px |
| 화면 속 강조 대상 글자 | 40 | 700 | 약 10px | 약 21px |
| 설명 목록 글자 | 36 | 700 | 약 9px | 약 19px |
| 번호표 숫자 | 30 | 800 | | |
| "설명용 목업" 표시 | 22 | 400 | | |

- **설명 글자는 화면 속 글자보다 크지 않게** 한다. 설명이 아니라 화면이 주인공이다.
- 원본 36px보다 작은 글자는 쓰지 않는다(표시 문구 제외). 모바일에서 읽을 수 없다.
- 읽을 필요가 없는 글(다른 메뉴, 지난 대화 목록)은 글자 대신 회색 막대로 그린다.
- 서체는 Pretendard를 먼저 쓰고, 없으면 기기 기본 한글 서체를 쓴다. 그림은 `<img>`로 들어가서 사이트 웹폰트를 쓰지 못한다. 그래서 서체마다 글자 폭이 조금 달라도 넘치지 않게 칸을 넉넉히 잡는다.

## 4. 번호표와 강조
- 독자가 누르거나 볼 곳은 **책의 포인트컬러 4px 테두리**로 감싼다. 한 그림에 3곳까지.
- 번호표는 지름 56px 원. 포인트컬러 바탕에 `onAccent` 색 숫자. 테두리 친 곳의 오른쪽 위 모서리에 걸친다.
- 설명 목록의 각 줄도 같은 번호표로 시작한다. 번호표만 보고 그림과 설명을 짝지을 수 있어야 한다.
- 설명은 한 줄 18자 안팎. 동작이나 이름만 쓴다("Claude 정보: 버전 보기").
- 화살표, 검은 말풍선, 그림자 띄운 설명 상자는 쓰지 않는다.

## 5. 색
- 바탕: `#F4F3F1`(사이트 panel 색) 한 가지.
- 화면 조각: 흰 바탕, 1px `#E7E5E2` 테두리, 모서리 16px. 그림자는 쓰지 않는다(테두리와 그림자를 같이 쓰지 않는다).
- 화면 속 글자 `#141414`, 흐린 글자 `#5E5B57`, 회색 막대 `#E7E5E2`.
- 강조색은 책의 `accent` 하나뿐이다. 다른 색을 섞지 않는다.

## 6. 표시
- 모든 그림 오른쪽 아래에 "설명용 목업"을 흐리게 적는다.
- 사람 이름, 이메일, 실제 대화 제목처럼 개인정보로 보이는 글은 그리지 않는다.

## 7. 정확성
- 버튼 글자, 아이콘 모양, 메뉴 순서는 그 책의 `outline.md`에 적힌 확인한 내용과 같게 그린다.
- 확인하지 못한 글자는 그리지 않는다. 회색 막대로 두거나 그림을 빼고 본문으로 설명한다.
- 그림의 `alt`에는 그림이 보여주는 동작을 한 문장으로 적는다.

## 8. 만드는 법
1. `src/books/<slug>/figures/<그림이름>.json`에 그림 설명을 쓴다(형식은 `scripts/mockup.mjs` 맨 위 주석).
2. `node scripts/mockup.mjs <slug>`를 돌린다. `public/books/<slug>/<그림이름>.svg`가 생긴다. 포인트컬러는 `book.json`에서 읽는다.
3. 뷰어에서 PC(1280px)와 모바일(375px)로 열어 글자가 넘치거나 겹치지 않는지 본다.

## 9. 점검표
- [ ] 화면의 한 부분만 그렸다
- [ ] 묶음이 가운데에 있고 바깥 여백이 고르다
- [ ] 설명 글자가 화면 글자보다 크지 않다
- [ ] 강조는 포인트컬러 하나, 3곳 이하이고, 번호표가 대상 바로 옆에 있다
- [ ] 확인한 글자만 그렸고, 개인정보로 보이는 글이 없다
- [ ] 모바일 폭에서 글자가 읽힌다
