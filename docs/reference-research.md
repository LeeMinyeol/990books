# 레퍼런스 조사: 브런치 · 와이어프레임 기법

조사일: 2026-11-04. 출처는 각 절 끝에 적었어요.

## 1. 브런치(brunch.co.kr)에서 가져올 것과 피할 것

브런치는 "글쓰기·읽기"에 집중한 서비스예요. 990books 뷰어는 "읽고 따라 하기"에 집중하므로 닮은 점이 많아요.

### 가져올 것
| 브런치의 장점 | 990books 적용 |
|---|---|
| 심플하고 깔끔한 GUI, 큰 커버 이미지 위의 제목 | 표지 장에 큰 제목 + 완성 결과물 미리보기. 장식은 최소화 |
| 폰트·색을 하나로 통일 (화이트·그레이·민트) | 흰 배경 + 포인트컬러 1개, 제목 폰트 1종 + 본문 Pretendard |
| 본질에 충실한 최소 기능, 웹과 앱의 동일 경험 | 뷰어 기능은 넘기기·진행률·복사·이어보기·스탬프로 제한. PC·모바일 같은 동작 |
| 옵션을 제한해 글에만 집중하게 함 | 슬라이드 서식은 데이터로 고정. 책 제작자가 정렬·크기를 바꾸지 않음 |
| 이미지가 감성을 만듦 (커버 사진 활용) | 책 카드와 표지에서 결과물 이미지를 대표로 사용 |

### 피할 것 (브런치가 아쉽다고 평가받은 점)
| 아쉬운 점 | 990books 대응 |
|---|---|
| 감성적 이름이 기능을 흐림 ("작가의 서랍", "글 읽는 서재") | 직관적 이름 사용: "이어보기", "나의 기록", "복사" |
| 작고 흐린 아이콘 | 터치 영역 44px 이상, 글자 대비 충분히 |
| 오른쪽으로 넘기면 다음이 나올 거라는 기대를 깨는 스크롤 | 좌우 넘기기는 항상 "오른쪽/왼쪽 = 다음/이전"으로 고정 |
| 콘텐츠가 기준 없이 쏟아짐 | 카드 정보 순서 고정(도구·비용 → 시간·장수 → 평점), 한 화면 한 동작 |
| 기능 설명 부족 | 첫 사용 시 한 줄 안내("키보드 ← →로도 넘길 수 있어요") |

## 2. 와이어프레임·워크플로우 기법

### 조사한 기법
1. **저충실도(low-fi) → 중충실도 순서**: 회색 박스와 실제 글로 구조부터 확인하고, 색·폰트는 나중에. (Figma 가이드)
2. **실제 콘텐츠로 검증**: lorem ipsum 대신 진짜 문구를 써야 줄바꿈·길이 문제가 일찍 드러나요.
3. **정보 구조(IA) + 사이트맵**: 화면이 어디에 놓이고 어떻게 이동하는지 먼저 그려요. 사이트맵을 봐야 길을 찾는다면 구조가 잘못된 거예요.
4. **사용자 흐름(User Flow)**: 화면(사각형)·행동·분기(마름모)를 선으로 이어 한 번에 보기.
5. **주석 달린 와이어프레임**: 콘텐츠 우선순위 번호, 인터랙션 메모, 반응형 동작, 접근성 메모를 함께 적어요. (wireframe-spec 스킬)
6. **상태별 화면**: 빈 상태·로딩·채워진 상태·오류를 모두 그려요.
7. **반응형 버전**: 모바일과 PC 와이어프레임을 따로 둬요.
8. **방향 2~3개 비교**: 구조가 정해지지 않았을 때만, 색이 아니라 "구조"가 다른 안을 비교해요. (html-wireframe 스킬)

출처: [Figma - What is Wireframing](https://www.figma.com/resource-library/what-is-wireframing/), 설치한 스킬 `wireframe-spec`(owl-listener/designer-skills), `html-wireframe`(plannotator/effective-html)

### 990books에 적용한 결과
- 와이어프레임 문서: [wireframe.md](wireframe.md) (사이트맵, 사용자 흐름, 화면별 주석, 상태, 반응형)
- 뷰어에 반영: 터치 영역 44px, 안내 문구 대비 개선 (아래 변경 내역 참고)
- 이후 새 화면(로그인, 내 서재, 결제 전 안내)은 코딩 전에 이 문서에 먼저 그린 뒤 구현해요.
