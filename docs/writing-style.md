# 문체 규칙 (2026-11-10)

99BOOKS의 모든 글(전자책, 오늘의 칼럼, 상세페이지 문구)이 따르는 규칙이에요. 인기 글 75편을 조사해서 정했어요.
글을 쓴 뒤에는 반드시 검사기를 돌려요: `node scripts/style-check.mjs <파일> --type column|deep|slide`

## 1. 핵심 규칙 10가지
1. 말투는 해요체. 사실을 못 박는 문장만 "~습니다"를 쓸 수 있어요(평서문의 20% 이하). "~한다"체는 쓰지 않아요.
2. 한 문장은 평균 25~42자. 60자를 넘으면 둘로 나눠요.
3. 한 문단은 1~3문장. 네 번째 문장이 나오면 줄을 바꿔요.
4. 첫 문장은 숫자, 장면, 질문 중 하나로 시작해요. 인사와 예고("오늘은 ~를 알아볼게요")로 시작하지 않아요.
5. 소제목은 그 구역의 결론을 말하는 문장으로 써요. "문단은 세 문장을 넘지 않아요"처럼요. "문단 길이"처럼 주제만 적지 않아요.
6. 숫자에는 기준을 붙여요. 언제, 누가 센 것인지 적어요. 확인하지 못한 숫자는 쓰지 않아요. 기준 시점은 출처를 실제로 연 날짜만 써요. 다른 문서에서 옮긴 숫자에는 "○○ 문서 기준"이라고 써요.
7. 한계와 예외를 숨기지 않아요. "다만 ~인 경우는 달라요"를 본문에 그대로 써요.
8. 낯선 용어는 처음 나올 때 한 번만 풀어요. 풀이는 그 문장 바로 뒤에 한 문장으로.
9. 강조(굵게)는 한 문단에 1번, 슬라이드는 한 장에 1번.
10. 독자는 상황으로 불러요("스토어를 운영 중이라면"). "여러분"은 쓰지 않아요.

## 2. 조사 방법과 한계
- 대상: 아이보스 칼럼, 채널톡 블로그, 큐레터, 퍼블리, 롱블랙. 사이트마다 15편, 모두 75편. 조사일 2026-11-10.
- 고른 기준(사이트마다 인기 표시 방식이 달라요)

| 사이트 | 고른 기준 |
|---|---|
| 아이보스 칼럼 | "인기 칼럼(최근 7일)" 1~10위 + 칼럼 첫 화면 상단 5편 |
| 채널톡 블로그 | 인기 순위가 없어서 블로그 첫 화면의 추천·최신 글 중 보도자료와 다시보기를 뺀 15편 |
| 큐레터 | 인기 순위가 없어서 첫 화면 대표 글 4편 + 최신 글 8편 + 트렌드 분야 3편 |
| 퍼블리 | "퍼블리 인기 Top 5" + 첫 화면 추천 10편. 유료라서 **공개된 앞부분만** |
| 롱블랙 | 첫 화면에 표시된 평점 참여 수가 많은 노트 12편 + 최근 3편. 유료라서 **공개된 도입부만** |

- 재는 방법: 본문을 문장 단위로 나눠 글자 수(공백 포함)를 세고, 문장 끝말로 말투를 분류했어요. 사이트별로 15편의 가운데 값을 썼어요.
- 한계: 퍼블리와 롱블랙의 숫자는 도입부만 잰 값이에요. 채널톡과 큐레터는 "인기"가 아니라 "추천·최신" 글이에요. 문장 나누기는 자동이라 목록·인용에서 오차가 있어요.

## 4. 오늘의 칼럼 규칙

### 수치 기준 (검사기 `--type column`)
| 항목 | 기준 |
|---|---|
| 분량 | 공백 제외 1,000~3,000자 (2~5분 분량) |
| 평균 문장 길이 | 25~42자, 45자를 넘으면 불합격 |
| 60자 넘는 문장 | 15% 이하 |
| 4문장 이상 문단 | 10% 이하 |
| 해요체 | 평서문의 75% 이상 |
| "~습니다" | 평서문의 20% 이하 |
| 소제목(`##`) | 3~7개, 28자 이하 |
| 이모지 | 글 전체 2개 이하 |

### 구조
1. **제목**: 글에서 알게 되는 것 하나를 말해요. 질문형도 좋아요. 28자 이하.
2. **도입(2문단)**: 첫 문단에 숫자·장면·질문 중 하나. 둘째 문단에 "그래서 이 글이 무엇을 말하는지"를 한 문장으로.
3. **본문(소제목 3~5개)**: 소제목마다 사실 → 뜻 → 예외 순서. 사실에는 출처를, 뜻에는 근거를 붙여요.
4. **마무리(소제목 1개)**: 독자가 오늘 해 볼 수 있는 일 2~4가지. 여운이나 명언으로 끝내지 않아요.
5. **관련 책 연결**: 내용이 실제로 이어지는 전자책이 있으면 글 끝에 1권을 한 문장으로 소개해요. 없으면 넣지 않아요. 억지로 연결하지 않아요.

### 도입 유형 (셋 중 하나를 고른다)
| 유형 | 방법 | 예시 |
|---|---|---|
| 숫자 | 가장 놀라운 숫자 하나를 첫 문장에 | "마케터가 즐겨 읽는 글 75편을 골라 문장 길이를 쟀어요. 가장 짧은 곳은 30자, 가장 긴 곳은 48자였어요." |
| 장면 | 독자가 겪어 본 순간을 두세 문장으로 | "글을 다 썼는데 다시 읽기 싫을 때가 있어요. 틀린 곳은 없는데 눈이 미끄러져요." |
| 질문 | 독자가 속으로 하던 질문을 그대로 | "글이 안 읽힌다는 말을 들으면 무엇부터 고쳐야 할까요?" |

### 칼럼 내용 규칙
- 한 주제를 출처 3곳 이상에서 확인해요. 한 글의 구성이나 문장을 따라 쓰지 않아요.
- 분량을 채우려고 근거 없는 문장을 넣지 않아요. 모자라면 예시나 예외를 더하고, 그래도 모자라면 짧게 내요.
- 조사한 사실에 **우리 관점 한 단락**을 반드시 더해요. "그래서 무엇을 하면 되는지"가 관점이에요.
- 출처는 문장 안에 이름으로 밝혀요("펜실베이니아대 연구진에 따르면"). 수치는 기준 시점과 함께.
- 완성 예시: [docs/samples/column-sample.md](samples/column-sample.md) (검사기 합격본)

## 5. 전자책 규칙

### 5-1. 슬라이드형 (미니북, 실전 키트) — 검사기 `--type slide`
| 항목 | 기준 |
|---|---|
| 장 제목 | 22자 이하. 그 장에서 하는 동작을 말해요("30일 게시 계획표를 만들어요") |
| 본문 | 1~2문장, 문장당 40자 이하(목표 30자) |
| 강조 | 한 장에 굵게 1곳. 독자가 바꾸거나 눌러야 하는 것에만 |
| 입력값 | 프롬프트·설정값은 박스로 분리. 바꿀 부분은 `[ ]`로 표시 |
| 이모지 | 쓰지 않아요 |
| 준비물 장 | 작성 시점, 도구 이름, 버전을 적어요 |

- 한 장에 동작 하나. "A를 누르고 B를 입력해요"는 두 장으로 나눠요.
- 장 본문은 "무엇을 한다 + 왜 또는 어떻게 되는지" 순서예요. 예: "표 형태로 받으면 **붙여넣기**가 쉬워요."

### 5-2. 긴 글형 (심화 가이드) — 검사기 `--type deep`, 챕터 단위로 검사
| 항목 | 기준 |
|---|---|
| 챕터 분량 | 공백 제외 2,000~4,500자 |
| 평균 문장 길이 | 25~42자, 45자를 넘으면 불합격 |
| 60자 넘는 문장 | 12% 이하 |
| 4문장 이상 문단 | 10% 이하 |
| 해요체 | 평서문의 75% 이상 |
| "~습니다" | 평서문의 20% 이하 |
| 소제목(`##`) | 챕터당 5~8개. 아래 고정 소제목 6개를 포함해요. 단계 제목(`###`)은 세지 않아요 |
| 이모지 | 쓰지 않아요 |

챕터 구조는 항상 같아요. 여섯 소제목은 `##`로, 이 글자 그대로 써요. 완성 예시는 [docs/samples/deep-chapter-sample.md](samples/deep-chapter-sample.md)예요(검사기 합격본).
1. **이 장을 마치면** (3줄 이하): 독자가 갖게 되는 결과물이나 할 수 있게 되는 일.
2. **먼저 알아둘 것**: 정의부터 한 문장으로("스킬 파일은 AI가 일을 맡을 때마다 먼저 읽는 설명서예요").
3. **따라 하기**: 단계마다 `### 1. 기준을 문서로 옮겨요`처럼 번호와 동작으로 된 제목을 붙여요. 단계마다 입력값 박스와 확인 방법.
4. **자주 막히는 곳**: 증상 → 원인 → 해결을 표나 짧은 문단으로. 최소 2개.
5. **나쁜 예와 좋은 예**: 나란히 놓고, 무엇이 달라졌는지 이유를 붙여요.
6. **점검표**: 다음 장으로 가기 전에 확인할 3~5가지.

- 전문가다운 말투는 **단정 + 근거 + 조건**에서 나와요. "A가 좋아요"가 아니라 "글이 3개 이상이면 A를 쓰세요. B는 수정할 때마다 전체를 다시 만들어야 해요."
- 경력이나 경험을 내세우는 문장("10년간 ~해 온 제가")은 쓰지 않아요. 지어낸 사례·수치·후기도 쓰지 않아요.
- "직접 해 봤어요", "해 보지는 않았어요" 같은 말은 넣지 않아요.

### 5-3. 표지·상세페이지 문구
- 제목 공식: 도구 + 결과물 + 걸리는 시간. 예: "클로드로 인스타 한 달치 콘텐츠, 하루 만에 뽑기"
- 부제는 받게 되는 결과물을 구체적으로. "30일 게시 계획표와 캡션, 해시태그까지 한 번에 만들어요."
- 후킹은 결과물로만 해요. 수익·조회수·성공을 약속하지 않아요.
- 버튼은 누르면 일어나는 일을 말해요("앞 3장 무료로 보기").

## 7. 금지·주의 표현
**쓰면 불합격**
- "여러분"
- 수익·매출·조회수·성공을 보장하는 말, 수익 금액으로 후킹하는 말
- "무조건", "누구나 쉽게", "100% 효과"
- "직접 해 봤어요", "해 보지는 않았어요"
- 투자 종목, 매수·매도 시점, 수익률
- "확인 필요", "미정"처럼 채우지 않은 자리
- 지어낸 경력·수치·사례·후기

"수익을 보장하지 않아요"처럼 부정하는 문장은 불합격이 아니에요. 검사기는 따옴표 안의 인용도 보지 않아요.

**주의(검사기가 표시, 사람이 판단)**
- 예고만 하는 문장: "알아보겠습니다", "살펴볼게요"

## 8. 쓰는 순서
1. 종류를 정해요: 칼럼(`column`), 슬라이드형(`slide`), 긴 글형(`deep`).
2. 4장 또는 5장의 구조대로 뼈대(제목, 소제목)를 먼저 써요. 소제목은 결론 문장으로.
3. 본문을 써요. 문단마다 1~3문장.
4. 검사기를 돌려요. 불합격(✗)은 모두 고쳐요. 주의(△)는 6장의 예시처럼 고칠 수 있는지 봐요.
5. 소리 내어 읽듯 처음부터 읽으며 숨이 차는 문장을 나눠요.
6. 사실·수치·출처를 하나씩 다시 확인해요. 확인하지 못한 것은 지워요.
